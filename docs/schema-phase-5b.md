# Schema, phase 5b

Migration `db/migrations/0006_confused_changeling.sql` is generated by `drizzle-kit generate` from `db/schema.ts`. It has not been applied; the owner applies it with `npm run db:migrate`. No new tables, so no new row-level-security policies: the existing `user_settings` and `financial_assumptions` owner policies still apply. The Drizzle connection bypasses RLS, so every query still filters by the signed-in user's id.

Scope: net worth history, portfolio allocation targets, insights, the scenario calculator and in-app reminders. History is replayed from the ledger and the price, valuation, rate and loan records as of each date; nothing is stored and there is no cache to invalidate.

## Changed tables

- `user_settings` gains:
  - `target_stocks`, `target_gold`, `target_clouds`, `target_cash` (`numeric(6,5)`, null): the target share of each class as a fraction. CHECK `user_settings_target_mix_check`: all four null, or all four set, each 0..1, summing to 1 within 0.00001.
  - `insight_min_percent` (`numeric(5,4)`, default 0.15) and `insight_min_amount` (`bigint` piasters, default 50000): a spending change is an insight only if it reaches both. CHECK: both >= 0.
  - `remind_review`, `remind_recurring`, `remind_stale`, `remind_goal`, `remind_budget`, `remind_savings` (`boolean`, default true): one switch per reminder kind.
- `financial_assumptions` gains `income_growth` (`numeric(8,6)`, null): yearly income growth for the scenario calculator (0.05 = 5%).

## Engine (`lib/finance-core`)

- `history.ts`: `samplingDates(range, firstDate, today)` (daily up to 3 months, weekly up to a year, monthly beyond, first and last date always included, at most 100 dates), `seriesFromSnapshots` (net worth, cash, investments, debt; a negative credit card is debt), and `snapshotsAsOf`, the in-memory as-of evaluation built on `accountBalance`, `outstanding` and the caller's portfolio valuation.
- `portfolioMix.ts`: `mix` (value and share per class; shares by largest remainder, exactly 100.00%), `validateTargets`, `vsTarget` (EGP above or below target per class; information only).
- `insights.ts`: `buildInsights` (ranked by EGP impact), `topN`. Each insight carries its text parts, named inputs and a plain-text formula. No comparison before 2 full months; budget state, goal status, allocation share, stale values and pending items work from day one.
- `scenario.ts`: `projectScenario`. Yearly rows, goal outcomes, required monthly amounts, an inflation view, and the assumptions it used. Runs in the browser and changes nothing.
- `reminders.ts`: `buildReminders`.

## Fixes

- `liabilities.ts`: `validateLiabilityHistory` checks the balance in date order, so a payment dated before the borrowing that funds it is refused. `outstanding()` still clamps at 0 for legacy data. `validatePayment` is unchanged.
- `recurring.ts`: `upcomingInMonth` lists a pending row with its own amount, category and account, even when its template is paused or gone; only not-yet-generated occurrences come from the templates. A pending `RecurringRow` now carries `type`, `amount`, `categoryId` and `accountId`.
- `budget.ts`: `level` is now `ok | warn | alert | over`. `over` means spending is above the budget; `alert` means past the configured alert level without exceeding it.

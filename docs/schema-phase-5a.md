# Schema, phase 5a

Migration `db/migrations/0005_overconfident_kronos.sql` is generated by `drizzle-kit generate` from `db/schema.ts`. It has not been applied; the owner applies it with `npm run db:migrate`.

Every new table has `user_id -> auth.users (cascade)`, row-level security enabled and an `<table>_owner_all` policy (`user_id = auth.uid()`). The Drizzle connection bypasses RLS, so every query still filters by the signed-in user's id.

Scope: budgets, recurring transactions, spending analytics, the monthly review and the emergency-fund target. Net worth history, charts, insights, target allocation, the scenario calculator and reminders are not part of this phase.

## New enums

`recurring_frequency` (`weekly`, `monthly`, `yearly`), `goal_target_mode` (`manual`, `expense_months`).

## New tables

| Table | Columns and constraints |
|---|---|
| `budgets` | `category_id -> categories` (null = the overall budget), `amount` (bigint piasters, > 0), `created_at`, `updated_at`. Standing amounts, not per-month rows. Unique `(user_id, category_id)` where the category is not null, and a unique `(user_id)` where it is null: one overall budget and one per category. That the category is an expense category is checked in application code |
| `recurring_templates` | `name`, `type` (`transaction_type`, CHECK limited to `INCOME` / `EXPENSE`), `amount` (> 0), `category_id`, `account_id` (receives an income, pays an expense), `frequency`, `start_date`, `end_date` (null, CHECK `>= start_date`), `auto_post` (default false), `active` (default true), `note`, `created_at`, `updated_at` |

## Changed tables

- `transactions` gains `recurring_template_id -> recurring_templates` and `recurring_due_date`, both null. CHECK: both set or both null. Unique index `(recurring_template_id, recurring_due_date)` with no status condition, so a skipped (void) occurrence is never generated again; rows with no template (NULL) never collide. Generation is lazy and idempotent: insert missing occurrences with `ON CONFLICT DO NOTHING` on that index.
- `goals` gains `target_mode` (`manual` by default) and `target_months` (null). CHECK: `target_months` is set exactly when the mode is `expense_months`, and is 1..60. `target_amount` stays: it is the manual target, and the fallback or last computed value in `expense_months` mode.
- `user_settings` gains `budget_warn_at` (`numeric(4,3)`, default 0.8) and `budget_alert_at` (default 1.0). CHECK: `0 < warn <= alert <= 2`.

## Rules

- A pending row has `status = 'pending'` and changes no balance, summary or budget until confirmed (status `posted`, amount and date may be adjusted). With `auto_post` the row is created `posted`. Skipping voids it.
- Editing a template affects only occurrences not yet generated. Reactivating an inactive template or moving its start date back creates the missing past occurrences on the next load.
- A recurring expense counts as fixed in budgets (never extrapolated per day); every other expense is variable.

## Engine (`lib/finance-core`)

- `recurring.ts`: `dueDates`, `missingOccurrences`, `upcomingInMonth`, plus the date helpers `addDays`, `daysBetween`, `dateOn`.
- `budget.ts`: `budgetStatus` (spent, remaining, percent used, projected month-end, `ok` / `warn` / `over`, `projectedOver`).
- `analytics.ts`: `spendingBy`, `monthTotals`, `fullMonths`, `trailingAverage`, `monthToDateComparison`, `change`, `yearOverYear`, and the noise thresholds `DEFAULT_NOTABLE_PERCENT` (15%) and `DEFAULT_NOTABLE_AMOUNT` (500 EGP).
- `review.ts`: `monthlyReview`, including the exact reconciliation `net worth change = saved + market change + adjustments`; a non-zero `difference` is reported, not hidden.
- `goals.ts`: `emergencyTarget` (target = months x average essential spending over the last 6 full months) and `shareValues` (largest-remainder split of one holding between goals; parts never exceed the holding). `shareValue` is unchanged and is for a single share.

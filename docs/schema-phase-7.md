# Schema, phase 7

Migration `db/migrations/0008_easy_misty_knight.sql` is generated by `drizzle-kit generate` from `db/schema.ts`. It has not been applied; the owner applies it with `npm run db:migrate`. The Drizzle connection bypasses row-level security, so every query still filters by the user's id (the one exception is `listUsersWithPush`, below).

Face ID sign-in (the other half of phase 7) changes no table.

## New table: `push_subscriptions`

One row per browser that turned notifications on.

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | primary key, `gen_random_uuid()` |
| `user_id` | `uuid` | not null, references `auth.users(id)` ON DELETE CASCADE |
| `endpoint` | `text` | not null, UNIQUE: the push service address for that browser |
| `p256dh` | `text` | not null: the browser's public key (base64url) |
| `auth` | `text` | not null: the browser's auth secret (base64url) |
| `label` | `text` | null: a short device description from the user agent, like "iPhone". No IP address, no location |
| `created_at` | `timestamptz` | not null, default now() |
| `last_success_at` | `timestamptz` | null: last accepted send |
| `failure_count` | `integer` | not null, default 0: failed sends in a row; the device is deleted at 5 |

Index `push_subscriptions_user_idx` on `user_id`. Row-level security is enabled with the usual owner policy `push_subscriptions_owner_all` (`user_id = auth.uid()`).

The generated SQL creates the table, enables RLS, adds the foreign key and the index, and creates the policy. It does nothing else.

`p256dh` and `auth` let anyone who holds them send a message to that browser, so they are server-only: no page, action result or log shows them, and the query helpers that return them are used only by `lib/push.ts`.

## Queries (`db/queries.ts`)

All filter by `user_id` except `listUsersWithPush`, which lists the distinct users that have a device. Only the daily reminders job (`app/api/cron/reminders/route.ts`) uses it, because that job runs without a session.

- `savePushSubscription`: upsert on `endpoint`. If the endpoint already belongs to another account nothing changes and it returns false. A repeat save from the same account refreshes the keys and resets `failure_count`.
- `deletePushSubscription` (by endpoint), `deletePushSubscriptionById`.
- `listPushSubscriptions`, `recordPushSuccess`, `recordPushFailure`.

## Not in the backup

Push subscriptions are per device: restoring a backup onto a new phone must not pretend that phone has notifications on, and the keys are secrets that do not belong in a file the person downloads. `lib/backup.ts` was checked and needs no change: it exports and restores a fixed list of tables, and `push_subscriptions` is not one of them. A restored account starts with no devices; each device turns notifications on again in Reminders.
